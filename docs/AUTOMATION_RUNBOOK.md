# 안전한 글 작성·배포 운영 절차

## 기존 자동화에서 바꾼 핵심

이전 방식은 데이터베이스 삽입, 원본 이미지 이동·삭제, 엑셀 완료 표시가 빌드와 실제 배포 확인보다 먼저 실행될 수 있었습니다. 새 운영에서는 원본을 마지막까지 보존하고, 공개 URL이 확인된 뒤에만 작업 완료로 처리합니다.

## 상태 흐름

```text
NEW → DRAFTED → REVIEWED → VALIDATED → BUILT → DEPLOYED → CONFIRMED → COMPLETED
```

- `NEW`: 엑셀과 이미지 폴더에서 작업 대상을 읽은 상태
- `DRAFTED`: `content/posts/`에 초안을 만든 상태
- `REVIEWED`: 근거와 문장을 검수하고 `editorial.status`를 `reviewed`로 변경한 상태
- `VALIDATED`: `npm run content:validate` 통과
- `BUILT`: `npm run build` 통과
- `DEPLOYED`: 원격 저장소에 업로드
- `CONFIRMED`: 실제 item.monster URL, 제목, 이미지, 쿠팡 링크를 확인
- `COMPLETED`: 그 후에만 엑셀을 O로 표시하고 원본 이미지를 보관 폴더로 이동

어느 단계에서 실패하든 이전 단계로 돌아갈 수 있어야 합니다. 실패한 작업 때문에 원본 이미지나 엑셀 행을 삭제하지 않습니다.

## 한 건 게시 순서

1. 엑셀의 상품명, 상품 URL, 이미지 폴더를 읽습니다.
2. 원본을 수정하지 않고 작업용 복사본을 만듭니다.
3. `content/templates/post.template.json`을 기준으로 글 파일을 만듭니다.
4. 확인 자료와 알 수 없는 정보를 `editorial.basis`에 모두 기록합니다.
5. [CONTENT_STANDARD.md](CONTENT_STANDARD.md)에 맞게 검수합니다.
6. `npm run content:validate`를 실행합니다.
7. `npm run build`를 실행합니다.
8. 생성된 정적 페이지의 제목, 본문, 이미지 경로, 광고 고지, 링크를 확인합니다.
9. 변경분을 커밋하고 원격 저장소에 업로드합니다.
10. 실제 URL이 정상 응답하고 링크가 열리는지 확인합니다.
11. 엑셀을 완료 처리하고 원본 이미지는 삭제하지 말고 날짜별 보관 폴더로 이동합니다.

## PC 전문가이드 게시 순서

1. 롱테일 검색 질문 한 개를 정하고 `npm run guide:new`으로 noindex 초안을 만듭니다.
2. CPU·칩셋·보드 제조사의 공식 사양, CPU 지원표, 매뉴얼을 찾아 `sources`에 확인 날짜와 함께 기록합니다.
3. 제조사 이미지는 미디어 키트의 이용 조건이 확인될 때만 저장합니다. 불명확하면 쿠팡 파트너스가 광고용으로 제공한 정확한 상품 이미지를 사용하고, 둘 다 없으면 글을 검수 완료로 넘기지 않습니다.
4. PC 전문 글 한 편에 실제 제품 사진 4장 이상과 자체 설명 도식 1장 이상을 준비하고, 2~3문단마다 관련 사진이 나오도록 소제목 사이에 나눠 배치합니다. 모델명·리비전·무선 기능이 사진과 본문에서 일치하는지 캡션까지 대조합니다.
5. 사실, 해석, 모델별 예외를 구분해 2,200자 이상 작성합니다.
6. 사람이 공식 문서와 문장을 대조한 뒤에만 `editorial.status: reviewed`, `indexable: true`로 변경합니다.
7. `npm run build`를 실행하면 검증, 정적 페이지 생성과 사이트맵 대조가 한 번에 수행됩니다.

사이트맵은 `src/app/sitemap.ts`가 검수 완료 콘텐츠를 읽어 빌드 때 자동 생성합니다. 새 글마다 XML을 직접 편집하지 않습니다. `updatedAt`이 실제로 바뀐 글만 `lastmod`가 바뀌며 noindex·legacy·draft 글은 사이트맵에 들어가지 않습니다.

정적 빌드에도 `reviewed + indexable` 글만 포함합니다. `legacy`, `draft`, `hidden` 원고는 `content/`에 보관하되 실제 사이트 페이지로 만들지 않습니다. 배포 준비 단계에서는 이전에 생성된 `post/`, `guide/` 폴더를 먼저 정리하므로, 예전 자동 생성 페이지가 서버에 남지 않습니다.

## 중단 규칙

다음 중 하나라도 해당하면 자동 게시하지 않고 `DRAFTED` 상태에서 멈춥니다.

- 쿠팡 링크가 없거나 상품이 품절·삭제됨
- 이미지와 상품명이 서로 다름
- 안전 인증이나 호환성처럼 구매 판단에 필수인 정보가 없음
- 의료·건강 효능을 검증할 1차 자료가 없음
- 자동 검사 실패
- Git 업로드 실패 또는 실제 페이지 확인 실패

## 복구 규칙

- 콘텐츠 오류: JSON 한 파일만 수정하고 다시 검증합니다.
- 빌드 오류: 엑셀과 원본 이미지는 그대로 두고 코드 오류를 수정합니다.
- 배포 오류: 마지막 정상 커밋을 유지한 채 새 커밋을 다시 업로드합니다.
- 링크 오류: `affiliate.url`을 수정하고 다시 빌드합니다.

자동화가 엑셀과 이미지 원본을 변경하는 기능은 마지막 `CONFIRMED → COMPLETED` 단계에만 연결해야 합니다.
